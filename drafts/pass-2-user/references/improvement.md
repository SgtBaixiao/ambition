# 让发现决定下一轮

用户要求递归优化、任务执行结果推翻假设，或需要维护本 Skill 时读取。递归是以具体观察改善下一轮方法；目标和明确约束沿用已有要求。

## 先说明本轮怎样结束

保留当前版本、已有结果和验证计划。说明本轮要解决哪个会影响判断的未知、怎样检查，以及什么结果足以结束或转入下一轮。投入与任务风险、可逆性、时限和预期收益相称。

未知不改变当前选择，或取得新信息的预期价值已不足以承担其成本和延误时，可以收尾；依据不足、存在重要矛盾时，选择能改变判断的下一项检查。访问、时间或资源先耗尽时交付临时结论、缺口和恢复条件。避免为满足轮数继续改写。

## 从执行结果修订

按当前版本执行适用分支，保留材料、观察与结果。每项修订说明：发现了什么、怎样影响任务或结论、改哪个假设或步骤、凭什么检查修订是否解决问题。文字更流畅或模型赞同只支持表达判断。

已有结果引发的修订视为探索。复查原失败是否解决，并用适当的新材料检查是否出现回退；新一轮验证的条件先记录。结果支持原方案时保留它，不能为了“优化”强行换路。需要改变用户最终目标、明确约束或授权范围时，单列待用户决定的条件。

完成依据：每项实质改动都对应可追查发现，并有相应检查；没有发现需要改动时明确保留当前方法。

## 维护可复用 Skill

方法规范的来源、规则的设计依据、实际行为结果和真实任务效果分别留证。先用 [完备性审查](completeness.md) 找出关键缺口，再按影响修补对应分支。单个例子优先修正局部规则；推广成通用要求需要足够理由。

较大修订可用现实请求和最少原始材料检查行为，评测前固定版本及判断标准，评测材料与改写时见过的例子分开。允许独立执行时，提供任务、Skill 和材料，保留完整输出，避免提前给答案。模型执行是行为观察，真实材料、现场结果与用户验收才支持使用效果。

检查目标和约束是否保留、原方案是否公平比较、结论是否超过证据、计划是否越界执行。格式验证、引用与包一致性另行检查。记录修订前后差异、回归结果和未验证部分；只在发现或新要求足以支持时继续修改。
