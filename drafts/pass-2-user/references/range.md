# 从其他领域借用有效方法

用于用户要求跨领域寻找方法、跳出专业边界或明确调用 range 的情形。目标是解决当前关键问题。保留明确目标、约束与交付物；占位任务用于形成通用方法，避免替用户创造项目。

## 先从名称转向行为

将“做一份报告、一个工具或一门课程”改写为谁在什么情境中，需要完成什么行为、改变什么结果。保留用户明确要求的交付物和形式；行为描述用于寻找方法。目标需要重新确认或实现路径需要重审时，按需读取 [altitude](altitude.md)，复用已有结论。

识别当前最关键的障碍和对应机制，例如辨认变化、传递证据、作出决策、协调操作、发现错误或掌握能力。机制应有原材料支持；缺少具体任务时给可填模板。避免仅从行业名称猜测问题。

完成依据：行为、结果和关键障碍明确，原要求保留，跨领域搜寻能对应需要解决的问题。

## 回答五个问题

先回答再给试验方案。简单任务用短段落或一个表，复杂任务按证据展开。

1. 将任务从交付物名称，描述为需要完成的行为与结果。
2. 哪些其他领域可能有成熟方法处理类似机制？说明结构上的相似处。
3. 借用什么具体方法、工具和流程？说明输入、步骤与可检查输出，角色名称不能代替方法。
4. 适用条件、预期收益和实施成本是什么？收益按已有证据或待验证假设报告。
5. 哪种迁移最值得先试？围绕当前关键障碍设计可实际验证的尝试。

完成依据：五问有任务相关的回答；选用方法能对应关键问题，而非增加领域或 Agent 数量。

## 核对方法怎样迁移

从源领域的实际规范、工具文档、原研究或成功与失败记录确认具体做法。区分方法在源领域已成熟、目标任务适用、实际工具可执行三个判断。需要查清关键未知时读取 [depth](depth.md)，引用按 [证据处理](evidence.md)核对。

对候选方法说明源问题、源机制与目标问题的对应关系，哪些步骤保留、哪些输入或流程要调整，以及哪里不匹配。表面线索可帮助检索案例，采用时重点核对共同作用的关系和约束，包括信息、空间、因果或组织关系。核对信息如何进入、行动如何改变结果、反馈与失败怎样被发现；结构相似帮助提出迁移假设，仍需目标任务验证。材料、尺度、时间、参与者或反馈不同可能使方法失效，列出最重要的不匹配处及检测办法。

探索类比可以提出，但正式称为成熟方法或推荐采用前，应核查源领域做法及目标适用条件；未完成核查就标为探索候选，把该核查放入尝试的进入条件。保留原专业方法作比较；可只借用一个有用步骤，避免搬入整套组织流程。

工具按已有能力与成本选择，先确认可取得的数据、环境和权限。无法执行时给出取得条件，不把推荐工具写成已经安装或采用。多代理只在独立子任务确有收益且授权允许时采用。

完成依据：所选方法具有具体步骤、可查来源和明确迁移依据；待验证假设与不匹配处已标明。

检索到案例、解释对应、产生候选和实际效果分别判断；有提示条件下的成功也不等于自发找到合适方法。迁移依据需要核查时读取 [方法来源](sources.md) 的 range 部分。

## 比较并选择试验

先筛明确约束，再比较解决关键障碍的预期作用、证据、数据与技能要求、设置成本、运行维护和转换负担。数量取决于实际可行方法，不为凑领域列清单。无值得引入的方法时保留原路径，并说明判断依据。

优先试成本可承受、结果可检查、能够区分关键假设的迁移。试验前写明基线、最小具体变化、材料和观察单位、结果与约束检查、通过和失败标准，以及结束后的采用、修改或放弃条件。尽量保持其他关键条件可比；多个方法必须组合时说明依赖和增量成本，结果先归于组合，单项贡献需要额外区分设计。阈值有依据；缺失时标为待确定。

尝试方案按 [方法选择](methods.md)确定验证方式；样本和时长由问题决定。先验证机制及可行性，再对扩大应用主张安排相应验证。计划、合成案例、实际试点和验收分别报告。

完成依据：方法选择有成本与证据依据，尝试可以检验当前关键问题；用户只要求方案时停在计划，已授权执行时按范围继续。

## 可复用请求

> 我当前需要完成的任务是：[具体任务]。请用 ambition 的 range，先把交付物名称转为需要完成的行为和结果，保留[明确目标、约束与交付物]。识别当前关键障碍，从其他领域寻找机制相似的具体方法，说明来源、工具、步骤、适用条件、收益依据及成本。比较原路径和可行迁移，选择最值得验证的一项，设计有基线、材料、观察、通过／失败及停止条件的尝试。按[仅计划／已授权执行范围]完成；优先解决关键问题。

新结果触发修订时读取 [迭代与停止](improvement.md)，记录实际发现和复查结果。方法越过原专业边界，目标和约束继续沿用用户要求。
