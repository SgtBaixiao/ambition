# 先确定值得完成的任务

保留用户明确的最终目标和约束，让任务更接近所需结果，让研究足以支持判断。`altitude` 检查任务是否是合适路径；`depth` 查清关键未知；`range` 迁移其他领域的具体方法。三者按需要选择。

## 选择本次分支

| 当前请求 | 读取与执行 |
|---|---|
| 重审目标与手段、寻找更直接的路径、使用 altitude | 读取 [altitude](references/altitude.md)，回答用户指定的四个问题，给出重定义的任务和实现方案。 |
| 深度调研、深化研究请求、使用 depth | 读取 [depth](references/depth.md)，先回答专业补充、原始材料、方法工具和外部验证，再改写并按模式执行。 |
| 跨领域寻找方法、跳出专业边界、使用 range | 读取 [range](references/range.md)，回答五问，核对方法迁移条件，选择并设计可验证尝试。 |
| 需要联用 | 目标需要重审时用 altitude；寻找其他领域方法时用 range；决定判断的未知用 depth。复用目标、材料和验证计划，无需固定执行全部分支。 |
| 检查已有研究或方法是否完备 | 读取 [完备性审查](references/completeness.md)，按对象选择分支；核对已有证据和执行状态。 |
| 根据实际结果递归改进任务方法或本 Skill | 读取 [迭代与停止](references/improvement.md)，先选当前所需分支，以具体发现触发修订和复查。 |

只点名 `$ambition` 时，根据请求内容选择分支并说明选择。仅有“帮我完成任务”、没有重审或深研需要时，按原任务工作，避免自动启动全部流程。用户只要求计划就交付计划；已授权执行则在该范围内继续完成。

## 保留目标和约束

用户明确提出的结果、范围、资源、时限、交付物和必须采用的方式都保留。目标解释来自用户原话或实际材料；推断标明依据与不确定性。会改变方案的缺失信息才向用户确认，同时继续不依赖该信息的工作。

当目标、约束或多个目标相互冲突时，说明冲突和可行选择，把需要改变的条件留给用户决定。新任务定义应能逐项追溯到原要求；方案改进仍服从当前授权范围。

## 按证据交付

方案提案、探索、验证和实际验收分别报告。比较包含原方案或适用现状，验证结果连到最终目标和约束；指标只是其可检查的表现。格式通过、模型赞同和合成案例不能证明真实效果。

完成依据随模式确定：计划需要任务、路径与验证可执行；审查需要关键缺口及影响明确；执行需要取得相应证据、完成适用验证，或如实交付条件性判断和未完成原因。续接时沿用已完成工作，仅更新变化部分。

方法归属或更新需要核查时，读取 [方法来源](references/sources.md)。交付文档与中文时遵守用户及环境的写作约定。本 Skill 自含方法规则，无需固定联网、子代理、产物数量或研究文件模板。
