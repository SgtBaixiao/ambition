# range 怎样完成跨领域迁移

研究日期：2026 年 11 月 24 日。本文为 ambition 的使用者和维护者说明：怎样把其他领域的方法用于当前关键问题，并保留两遍打磨的依据。最终交付是一个含 altitude、depth、range 的 Skill，以及可安装的公开发布版本。

range 的价值来自方法对关键问题的作用。领域和 Agent 数量不是结果，成熟方法也只有在对应机制与条件成立时才值得迁移。任务中的行为描述用于发现方法，用户明确的目标、约束与交付物仍作为判断依据。

## 按 ambition 规划本次开发

| 分支 | 本次怎样使用 |
|---|---|
| altitude | 将“新增一份 Skill 文件”追溯到让后续任务能找到、比较并验证跨领域方法；保留 ambition 名称、既存 depth／altitude、用户五问、两遍打磨及 GitHub 发布。 |
| depth | 专业补充是机制对应、迁移失效与成本；原始材料为用户要求、Felix 原文、现有规则及类比研究；通过文件、来源、冻结行为和实际安装分别验证。 |
| range | 借认知研究的关系映射检查类比，借工程方法核对功能、使用环境和失败条件，借版本管理与行为评测保留修订证据。每项借用都对应一个已识别缺口。 |

据此改写本次任务：在保留既存方法和用户目标的条件下，依据指定文章细化 range，再用一手方法资料及构造案例检查补齐迁移规则；两遍产物独立留存，形成统一可安装包，上传并发布到用户 GitHub，以实际发布和安装记录确认交付。

这次开发的 depth 前置问题具体落实如下，方法选择先于新增阅读范围。

| 改写前的问题 | 本次采用的做法 |
|---|---|
| 专业人士会补做什么？ | 除了汇集其他领域，方法设计者还会检查类比为何成立、哪些差异会使它失效，区分生成候选与证明效果，并用新任务检查规则是否越界。 |
| 从哪些原始材料开始？ | 从用户五问、既存 Skill、Felix 原文，以及类比理论与实验的完整论文开始；模型实际答复作为行为材料保存，避免只看它对自己的评价。 |
| 用什么方法和工具？ | 用关系映射核对源与目标，用原论文页图核对结果口径；实际采用 pypdf、macOS Vision OCR 和页图读取定位材料，用冻结文件哈希、隔离案例执行、ZIP 逐项比较、Git 和 skills CLI 检查交付。 |
| 什么外部结果能支持判断？ | 论文支持规则要素；另一个执行上下文的原输出支持所测行为；GitHub CI、远程发布资产和从远程安装后的文件哈希支持发布可用性。真实迁移收益仍须目标任务数据或现场验收，不能由模型赞同代替。 |
| 相应的研究请求 | 核对指定文章与原始类比研究，在保留目标和约束的前提下开发 range；按具体缺口修订，冻结两遍产物并用新案例检查；完成发布与安装核对，逐项报告证据支持的范围。 |

## 文章提供的概念起点

[Felix Rieseberg 的文章](https://felixrieseberg.com/how-to-be-more-ambitious-a-tutorial-for-humans-with-models/)发布于 2026 年 10 月 13 日，本轮取得原站正文并记录访问时间与哈希。作者区分 Speed、Altitude、Depth、Range。用户当前要求维护后三种方法，本轮没有另开发 Speed。

Range 一节建议把交付物名词改为行为，从更多领域寻找知识、工具和技巧，并提醒角色扮演不会自动改善结果。Blender 例子说明作者如何受到其他领域工具启发，不能证明任何网页都适合 3D。文章对《The Art of Innovation》的归属按作者说法记录，本轮未取得书籍原文作独立依据。

Depth 一节强调原始材料、专业工具、挑战假设与外部评判。Altitude 一节建议追溯预期结果，并用历史及同期运行比较新的流程。既存 ambition 已有这些执行规则，本轮只核对并增加出处，避免重写已稳定内容。

文章中的实践建议作为概念起点。对强目标的鼓励不代替可行性证据，提到多代理也不要求每次组建多个 Agent；用户明确提出优先解决关键问题，构成更具体的约束。

## 两遍产物怎样不同

| 产物 | 依据与实际变化 | 检查范围 |
|---|---|---|
| 第一遍，依据文章细化 | 将名词转行为、角色转方法的建议写成五问和完成条件；加入具体输入、步骤、输出、源与目标对应及尝试方案。 | 冻结十个文件；三个构造请求检查评审口径、入职错误操作与首页 3D 提议。 |
| 第二遍，结合用户要求扩展 | 明确机制匹配及失效条件；区分探索类比、源领域成熟程度与目标适用；用最小变化和组合归因限制试验；保持资源、材料、交付物和执行边界。 | 结合一手认知研究、原输出及新案例检查；两遍完整包与文件哈希留存。 |

第一遍案例未出现目标替换、约束丢失或执行越界。评审案例优先处理口径分歧，入职案例区分背诵与实际错误处理。首页案例提出局部互动类比，但未取得舞台或木偶制作的成熟做法来源，并明确其探索状态。这暴露了完成条件需要更清楚：未核查方法时可以设计探索，不能将它升级为成熟方法或既有成效。

本轮据此细化来源核查的进入条件，并要求方法组合的结果先归于组合。没有让更多领域加入检查，也没有为满足两遍要求宣称每遍都出现严重失败。详细行为判断见[验证记录](validation.md)。

## 迁移需要怎样的证据

用户五问分别落实为行为与结果、类似机制的领域、具体方法与流程、条件及完整成本、可验证尝试。来源核查同时检查方法在源领域的作用和在目标任务的匹配，不把原作身份或成熟工具当成适用证明。

对选中的方法，至少说明源领域解决什么问题、信息怎样进入、行动如何改变结果、反馈和失败怎样出现，以及目标任务中的对应项。不同材料、尺度、时间、人和反馈方式可能改变机制。源方法可以拆成一个步骤借用；搬入整套流程需要额外收益理由。

预期收益按来源适用范围或假设报告，成本包含材料取得、技能、设置、运行、维护及转换。工具推荐与实际安装分开；原路径继续比较。没有值得引入的方法时保留原路径，不为展示跨度制造路线。

尝试应改变最少必要环节，保留比较基线、材料版本、观察单位、约束和失败条件。多个方法组合时说明依赖，不能将组合改善直接归因于某一项。构造例子检查可执行性，真实目标环境决定适用效果。

## 完备性检查

| 用户要求及关键缺口 | 最终规则与检查依据 |
|---|---|
| 交付物转为行为和结果 | 行为描述用于找方法，明确交付物继续保留；评审和歌曲案例分别检查 PPT 与亲自创作。 |
| 找到其他领域的成熟方法 | 源领域成熟、目标适用与工具可用分开；未核查就保持探索状态，不能用机构或角色名称代替来源。 |
| 具体方法、工具和工作流程 | 候选写清输入、步骤、输出及源与目标的对应；首页、排队和创作案例检查具体方法及缺失条件。 |
| 条件、预期收益与成本 | 核对机制、不匹配及设置、运行、维护和转换成本；收益按证据或假设报告。 |
| 选择可实际验证的尝试 | 原路径参与比较，优先最小变化；写清材料、观察单位、基线、通过／失败和停止条件。 |
| 跨领域引入可能增加无用流程 | 五分钟核对案例允许保留原清单；已定按钮文案不启动完整方法。 |
| 类比和试验可能产生过强结论 | 排队案例检查模型条件与尾部指标；组合案例检查归因；depth 回归检查零记录与真实零错误的区别。 |

目前没有需要另增通用分支的关键缺口。各领域的具体数据、方法文档、成本和阈值仍由实际任务取得；本 Skill 提供判断与验证规则，不声称已经替所有领域完成适用性研究。

## 方法资料与检索范围

本轮核心一手依据是指定文章、类比认知研究，以及既存 NASA 的功能与目标环境指导。类比论文的核查与访问边界见[原始研究笔记](analogy-primary-notes.md)，来源正文与定位汇总到 Skill 的[方法来源](../skills/ambition/references/sources.md)。NASA 4.1.1.2.4 的使用情景描述、非正常条件和人机分工支持从行为分析需求，2.4 区分符合要求与用途成立；它们不证明跨领域普遍效果。

Gentner 1983 年的[结构映射理论](https://groups.psych.northwestern.edu/gentner/papers/Gentner83.2b.pdf)关注相互约束的关系系统，第 165 页注 11 区分生成推论和判断可信性；这是理论框架，不能把关系匹配当作效果验证。[Gick 与 Holyoak 1980 年实验](https://reasoninglab.psych.ucla.edu/wp-content/uploads/sites/273/2021/04/Gick-Holyoak1980Analogical-Problem-Solving.pdf)显示目标、约束及提示条件影响构造题中的解法，也记录了违反题设的迁移想法。[Holyoak 与 Koh 1987 年实验](https://reasoninglab.psych.ucla.edu/wp-content/uploads/sites/273/2021/04/HollyoakKoh1987.pdf)进一步区分表面与结构差异的作用；其材料范围和计分条件有限，不能推广为所有真实任务效果。

因此第二遍保留“表面线索辅助检索、采用时核对关系及约束”的分工，并分别观察案例检索、对应解释、候选生成和实际效果。原研究用于解释为什么需要这些检查，用户五问和目标保留要求决定本 Skill 的最终规则。

补充检索尝试了 Biomimicry Toolbox 的 process、abstract、evaluate 页面、AskNature 分类和 IDEO 的 analogous inspiration 页面；本轮超时、连接重置或返回 403，未读到正文，不用作实质来源。公开英语方法资料是本轮范围；没有执行系统综述，未声称所有领域都已覆盖。

来源正文快照只留在本地研究目录，公开仓库发布原创规则、归纳、构造请求、原执行输出及检查记录。引用链接和定位保留，未将第三方全文装入 Skill。

## 怎样完成这一轮

关键问题有执行规则，一手来源可定位，已发现缺口有修订和相应检查；包、安装和实际 GitHub 发布得到核对时完成本轮。后续真实任务发现新失败时再按迭代规则修订。

本次构造行为检查没有有无 Skill 的随机对照，也不是跨领域代表性样本。格式、模型行为、真实任务效果和发布状态分别报告，避免用其中一项覆盖其他尚未验证的主张。
